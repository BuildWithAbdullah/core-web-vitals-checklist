# Examples

Eleven defects, each as a failing page and a corrected one. A static
detector in [`tools/checks.mjs`](../tools/checks.mjs) asserts in CI that the
defect is present in `fail.html` and absent from `pass.html`, and that no
`pass.html` carries any of the other ten defects.

This file is generated by `node tools/verify.mjs --write`. Edit the checks,
not the table.

## LCP

| Example | Phase | What the detector proves | What it does not prove |
|---|---|---|---|
| [The hero image is lazy loaded](01-lazy-hero/) | load delay | The browser is told not to prioritise the first image on the page, so it is discovered late no matter how small it is. | That this image is the LCP element. Only field attribution decides that, and on a text-heavy template it often is not. |
| [The hero is a CSS background image](02-css-background-hero/) | load delay | The preload scanner cannot see the image. It is discovered only once the stylesheet has arrived and been applied, which adds the whole CSS round trip to load delay. | That the background is the LCP element. A background image is an LCP candidate only when it is the largest painted element. |
| [Stylesheets are chained with @import](03-css-import-chain/) | render delay | The second stylesheet is not requested until the first has arrived and been parsed, so two render blocking round trips happen one after the other instead of together. | How much time this costs. On a fast connection with warm DNS it can be tens of milliseconds, and on a slow mobile connection it can be a second. |
| [A web font blocks text rendering](04-font-display-block/) | render delay | With no font-display descriptor the browser hides the text for up to three seconds waiting for the font file, and text is frequently the LCP element. | That switching to swap is free. It is not: swapping fonts with different metrics is a CLS source, which is what example 08 is about. |

## CLS

| Example | Phase | What the detector proves | What it does not prove |
|---|---|---|---|
| [An image reserves no space before it loads](05-unsized-image/) | layout shift | The image occupies zero height until its bytes arrive, then everything below it moves. This is the single most common CLS source. | That the shift is large enough to matter. A shift below the fold that nobody has scrolled to does not count towards CLS. |
| [A third party embed has no reserved space](06-unreserved-embed/) | layout shift | The slot is empty until a network response arrives from a server you do not control, and then it pushes the page down at an unpredictable moment. | What size to reserve. An ad slot that fills variably is a design decision, not a code fix, and reserving the wrong height trades a shift for a gap. |
| [A banner is injected at the top of the page after load](07-injected-banner/) | layout shift | Content is inserted above content the user is already reading, which moves the whole page. Consent banners and promotion bars are the usual owners. | That the banner is the largest shift. A CLS score is a sum of session windows, and a single dramatic shift can still score below a series of small ones. |
| [A font swaps into different metrics](08-font-metric-mismatch/) | layout shift | The fallback font and the web font take different amounts of space, so every line of text reflows at the moment of the swap. This is the CLS that appears after somebody fixes example 04. | The size of the shift. That depends on how far apart the two fonts actually are, which you measure rather than assume. |

## INP

| Example | Phase | What the detector proves | What it does not prove |
|---|---|---|---|
| [An event handler runs to completion without yielding](09-long-task-handler/) | processing | The handler holds the main thread for the whole of its work, so the browser cannot paint a response until it finishes. INP measures exactly that wait. | That the handler is slow. A loop over ten items is fine. The detector flags the shape, and the field data says whether the shape costs anything here. |
| [Layout is read and written in the same loop](10-layout-thrash/) | presentation | Each read forces the browser to flush the writes from the previous iteration, so a loop over n elements causes n synchronous layouts instead of one. | That splitting the loop is enough. If the write itself changes layout for the whole page, batching moves the cost rather than removing it. |
| [A third party script blocks parsing in the head](11-blocking-third-party/) | input delay | Parsing stops until the script has been fetched, parsed and executed. That delays first paint, and the execution occupies the main thread while the user is trying to interact. | That defer is the right fix. A tag manager that must run before consent, or an anti-flicker snippet, has a reason to be where it is, and the fix is to argue about the requirement rather than the attribute. |

## The limit that applies to all of them

Every check here is static. It reads markup and stylesheets and looks for
a shape. None of them measures anything, none of them runs the page, and
none of them can tell you whether the defect it found is costing you
anything on real visits. That is what the field data in
[`measure/`](../measure/) is for. Use these to know what to look for and
what the fix is. Use attribution to know whether it is worth doing.
